# RAG, SFT и RL для языковой модели

> **Статус: прототип v1.** Эта обвязка написана под первую предметную модель (закупки, 2 типа ошибок) и пока не переведена на среду v2. В `python -m audit_env verify` она не входит, её тесты лежат в `tests_extras/`. Актуальное обучение на CPU описано в [micro-model.md](micro-model.md).

Большая модель действует как аудитор. За ход она генерирует один JSON-объект, среда возвращает результат инструмента, на финише независимый оценщик проверяет тип, сумму, валюту и прочитанные доказательства. Модель получает только публичный контекст эпизода.

## Поиск во время эпизода

`RagAuditEnv` добавляет два необязательных инструмента к стандартной `AuditEnv`. У инструментов общий лимит 100 шагов. Основной конкурсный контракт остаётся доступен через `AuditEnv`.

- `{"type":"search_records","query":"payment_suspense","table":"ledger","limit":6}` возвращает записи из локального BM25 индекса и их ID.
- `{"type":"search_records","table":"ledger","link":{"field":"invoice_id","id":"<invoice_id>"},"limit":12}` раскрывает источники по точной связи. Связь можно сочетать со строкой запроса. Разрешены `invoice_id`, `payment_id` и `entity_id`.
- `{"type":"group_ledger","by":"invoice_id","account":"expense","min_count":2,"limit":12}` группирует открытые строки. Ключи групп помогают найти кандидатов. Для цитирования агент отдельно загружает исходные документы и строки.

Индекс строится заново из открытых таблиц каждого эпизода. Документы не уходят в сервис поиска. Поиск подтверждает просмотр источников, группировка сама по себе доказательств не добавляет.

## Подготовка данных

```bash
make llm-data
python3 -m audit_env.llm_data build/llm-small --train-episodes 8 --dev-episodes 4
```

Экспорт использует открытую демонстрационную политику, которая вызывает инструменты и сверяет документы. Проверяющий принимает только успешные демонстрации. В обычном запуске создаются 96 train и 24 dev эпизода. Для своего распределения передайте `--suite configs/open-suite.v1.json` и используйте тот же аргумент в RL и eval. Выходной каталог должен быть новым.

| Файл для каждого сплита | Формат |
| --- | --- |
| `*.sft.jsonl` | `prompt` и `completion` как списки chat-сообщений. Completion содержит ровно одно действие ассистента. |
| `*.preferences.jsonl` | `prompt`, `chosen`, `rejected`. Оба ответа проверены на одном и том же префиксе. |
| `*.rollouts.jsonl` | Эпизод, полный журнал инструментов и терминальная награда, отдельно от диалога. |
| `manifest.json` | Версия, размеры сплитов и контрольные суммы файлов. |

Train и dev имеют независимые последовательности seed. Экспорт не включает seed, эталон или журнал мутаций. Терминальная награда предназначена для тренера и отсутствует в промпте. Пары предпочтений готовы для внешнего DPO-тренера. Встроенные команды обучают SFT и RL.

## Обучение и проверка

Нужна локальная chat-модель Hugging Face с Safetensors, токенизатором с chat template и EOS. Поддерживается один CPU, MPS или CUDA-ускоритель. Для больших весов выбирайте CUDA с подходящим объёмом памяти. В команде не загружаются модели с Hub и не исполняется пользовательский код из каталога модели.

```bash
python3.12 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements-llm.txt
make llm-smoke PYTHON=python

export HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1
BASE=/absolute/path/to/local-chat-model
python -m audit_env.hf_train sft --model "$BASE" --dataset build/llm \
  --output build/adapters/sft --steps 200 --gradient-checkpointing

python -m audit_env.hf_train rl --model "$BASE" --adapter build/adapters/sft \
  --output build/adapters/rl --steps 32 --group-size 4 --learning-rate 1e-5

python -m audit_env.hf_train eval --model "$BASE" --adapter build/adapters/rl \
  > build/llm-dev-report.json
```

SFT считает loss только на токенах ответа ассистента. Примеры, которые не вмещаются в окно контекста, пропускаются и учитываются в отчёте. Модуль RL сэмплирует несколько прогонов на одном train-эпизоде и обновляет LoRA по относительной терминальной награде. Группа с одинаковой наградой даёт нулевой обучающий сигнал, что видно в отчёте. Закрытый `eval` запускает жадную генерацию на dev и сохраняет метрики и монитор каждого эпизода у проверяющего. Для измерения прироста запустите один и тот же eval на исходной модели, SFT и RL с одинаковыми параметрами эпизодов и генерации.

`make llm-smoke` создаёт маленькую случайно инициализированную chat-модель на CPU. Он проверяет шаг SFT, сохранение и загрузку адаптера, генерацию действия и изменение весов от двух разных наград среды. Это проверка тракта обучения. Показатели для больших моделей пока не измерялись.

Увеличивайте `--max-length` и `--max-new-tokens` в пределах окна выбранной модели. Для первого запуска можно уменьшить выборку и число шагов. Бюджет эпизода 60 секунд включает время инференса. Если большая модель регулярно превышает бюджет, сравнивайте с тем же лимитом на самом быстром доступном устройстве. Покрытие датасета ограничено двумя реализованными типами ошибок. Для следующего этапа добавьте валютный курс, границы периода и взаимодействующие ошибки в генератор и демонстрационную политику.

Документация форматов и адаптеров: [Transformers Chat Templates](https://huggingface.co/docs/transformers/chat_templating), [PEFT LoRA](https://huggingface.co/docs/peft/en/package_reference/lora).
