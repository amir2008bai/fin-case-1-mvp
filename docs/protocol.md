# Контракт и граница доступа

`AuditEnv.reset(seed, config)` вызывается проверяющим и возвращает `(observation, info)`. `AuditEnv.step(action)` возвращает `(observation, reward, terminated, truncated, info)`. На старте наблюдение содержит задание, манифест, политику и 100 доступных действий.

| Действие | Поля JSON кроме `type` | Результат |
| --- | --- | --- |
| `list_records` | `table`, необязательные `cursor`, `limit` (1–50) | `records`, `next_cursor` |
| `get_record` | `table`, `id` | Одна строка по ID таблицы |
| `get_document` | `doc_id` | Полный документ счёта или платежа |
| `calculator` | `expression` | Десятичная строка, 50 значащих цифр расчёта |
| `submit` | `findings` | Завершение эпизода |

Таблицы называются `ledger`, `invoices`, `payments`, `fx`. Ошибки просмотра расходуют шаг. На 100-м шаге ещё можно отправить ответ. Исчерпание лимита, истечение 60 секунд и ошибка транспорта дают усечение и пустой итог. В открытом режиме награда за усечение равна −1. Остальные промежуточные награды равны 0.

Пример запроса:

```json
{"type":"list_records","table":"ledger","cursor":null,"limit":50}
```

Отправка чистого ответа:

```json
{"type":"submit","findings":{"episode_id":"episode_from_manifest","findings":[]}}
```

Поля каждого вывода: `type`, `affected_ids`, `claimed_amount_minor`, `currency`, `evidence_ids`, `explanation`. Типы первой версии — `duplicate_invoice` и `payment_allocation`. Последовательность ID внутри набора не влияет на совпадение, повторы ID делают вывод невалидным. Заявленные доказательства должны быть выданы текущим эпизодом. Сопоставление максимизирует число пар с помощью увеличивающих путей. При нескольких вариантах порядок обхода задаётся порядком выводов и сортировкой по `issue_id`. Допуск первой версии — 0 минимальных денежных единиц.

Награда следует формуле задания `clip(2 * F1 - 1 - .002 * inspection_steps, -1, 1)`. Шаг отправки исключён из стоимости расследования. При пустом эталоне и пустом ответе F1 равен 1, P и R равны 0. Некорректная структура ответа завершает эпизод с −1. В закрытом режиме итоговое `reward` в API равно `null`, диагностический результат хранится у проверяющего.

## Запуск вне процесса агента

Проверяющий передаёт по stdin одну JSON-строку с полями `observation`, `reward`, `terminated`, `truncated`, `info`. Агент отвечает ровно одним действием в stdout и сбрасывает буфер. Ограничение на ответ — 256 КиБ UTF-8. Проверяющий пишет терминальный шаг в свою траекторию и останавливает агент. Код процесса, сетевое окружение и диагностика проверяющего в протокол не входят.

В закрытом режиме доверенный CLI держит истину, seed и журнал изменений в своём процессе. У отдельного контейнера агента нет каталогов хоста и сети. Команда задаёт ограничения CPU, памяти и процессов, непривилегированного пользователя и корень в режиме чтения. Образ агента должен предоставлять вход `python -m audit_env.agents <policy>`. Для нестандартного образа он может реализовывать этот же протокол с собственным кодом модуля. Обычный подпроцесс предназначен для доверенных локальных тестов.

Экспорт кладёт `manifest.json`, `policy.json`, `ledger.csv`, `invoices.jsonl`, `payments.jsonl`, `fx.csv` под `public/`. В CSV отсутствие ссылки записывается строкой `null`; в JSON используется `null`. В `private/` хранятся `truth.json` и `provenance.json`. В артефакты агента включайте лишь `public/` и разрешённые журналы.

В `trajectories.jsonl` шаг 0 содержит стартовое наблюдение, а последующие шаги фиксируют действие и результат. Метрики времени остаются во внешнем отчёте CLI. Для побайтового повтора используйте те же версию Python, код, seed, конфигурацию и действия. Реальный тайм-аут зависит от скорости запуска, поэтому тест времени использует часы с управляемым временем.
