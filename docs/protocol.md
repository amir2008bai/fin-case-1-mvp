# Контракт среды и протокол

## reset / step

- `AuditEnv.reset(seed: int, config: Config | dict | None = None)` возвращает `(observation, info)`. Вызов `AuditEnv().reset(seed)` без конфига и ключа использует открытый набор. Для `Config()`, закрытого запуска и явно заданного ключа сохраняются прежние правила. Первое наблюдение содержит `task`, `manifest`, `policy`, `tools` и `remaining_steps = 100`, а `info = {}`.
- `AuditEnv.step(action: dict)` возвращает `(observation, reward, terminated, truncated, info)`. Все значения JSON-совместимы.
- `AuditEnv.load_episode(episode)` загружает готовый эпизод: сгенерированный или прочитанный из папки через `episode_io.load_episode`.
- `AuditEnv(training=True)` — открытый режим: терминальная награда возвращается политике. При `training=False` (закрытый режим) награда равна `None`, результат остаётся у оценщика в `env.outcome`.

Одинаковые `seed`, `config`, ключ, версия и действия воспроизводят записи, переходы и награды. `reset` изолирует состояние эпизода.

## Действия

| Действие | Поля | Результат |
|---|---|---|
| `list_records` | `table` ∈ {ledger, invoices, payments, fx}, `cursor` (строка или null), `limit` от 1 до 50 | `{"records": [...], "next_cursor": str \| null}`. Курсоры стабильные и привязаны к таблице и эпизоду |
| `get_record` | `table`, `id` (`row_id` / `invoice_id` / `payment_id` / `fx_id`) | запись |
| `get_document` | `doc_id` | документ: поля таблицы плюс `doc_type`, `document_kind` (`act` — акт Р-1, `waybill` — накладная З-2), `title`, `number`, контрагент, `purpose` (для платежа), договор, статус, `vat_invoice` (ЭСФ, если есть НДС) |
| `calculator` | `expression`: только `0-9 . + - * / ( )` и пробелы | результат как десятичная строка (Decimal, 50 знаков) |
| `submit` | `findings` (см. ниже) | завершает эпизод: `terminated = true` |

Неизвестное действие, лишнее поле, неизвестная таблица или ID, неверный курсор, `limit` вне диапазона или недопустимое выражение дают `{"error": "<код>", "remaining_steps": n}`. Награда при этом 0.0, эпизод продолжается, шаг расходуется.

Коды ошибок: `invalid_action`, `unknown_table`, `unknown_id`, `invalid_limit`, `invalid_cursor`, `invalid_expression`. Шаг до `reset` возвращает ошибку `reset_required`, шаг после завершения — `episode_finished`; флаги завершения при этом сохраняются.

## Лимиты и завершение

- Не больше 100 шагов, включая отправку ответа. Сотый шаг может быть только `submit`, иначе эпизод обрывается (`truncated = true`).
- Время эпизода — 60 секунд, по истечении тоже обрыв. Это лимит оцениваемых прогонов (`AuditEnv`, `runner.py`). Интерактивные адаптеры, где действует человек или LLM, — сессии API для UI и сервер MCP — заводят среду с `interactive=True`: у сессии UI 1 час, у MCP 30 минут с момента `initialize` (`--timeout`). Лимит 100 шагов и все остальные правила у них те же.
- При обрыве наблюдение равно `{"status": "truncated", "findings": [], ...}`. Пустой ответ оценивается по формуле: на чистых книгах это 1 − 0.002·шагов, на книгах с ошибками −1.
- Промежуточная награда всегда 0. Подсказок о правильности по ходу нет.

## Выводы

```json
{"episode_id": "...", "findings": [{"type": "fx_rate", "affected_ids": ["payment_..."],
  "claimed_amount_minor": 4150, "currency": "KZT", "evidence_ids": ["doc_...", "fx_...", "row_..."],
  "explanation": "коротко"}]}
```

Допускаются до 30 выводов, 1–10 уникальных ID доказательств на вывод и до 1000 символов объяснения. Сумма задаётся целым числом от −10¹⁸ до 10¹⁸ в минорных единицах. Нарушение структуры даёт −1 и ошибку `invalid_submission` в журнале оценщика.

`explanation` нужен людям и на оценку не влияет: тот же ответ с любым текстом получает ту же награду. Это проверяет атака `persuasion` против контроля `persuasion-plain` (`python -m audit_env attacks`).

| Тип | `affected_ids` | `claimed_amount_minor`, валюта | Допуск | Допустимые наборы доказательств |
|---|---|---|---|---|
| `duplicate_invoice` | оба `invoice_id` | `total_minor` повторного счёта, валюта счёта | 0 | оба `doc_id` и строки Кт 6010 обоих счетов; или оба `doc_id` и их строки Дт 1210 признания |
| `payment_allocation` | `payment_id` | сумма Кт 3510, которая должна была погасить 1210, KZT | 0 | `doc_id` поступления и счёта, строка Дт 1030 и строка Кт 3510 |
| `fx_rate` | `invoice_id` или `payment_id` | \|проведено − правильно\| в KZT | 2 | `doc_id`, `fx_id` правильной даты, строка Кт 6010 или Дт 1210 (счёт) либо Дт 1030 (поступление) |
| `period_cutoff` | `invoice_id` или `payment_id` | Кт 6010 счёта в периоде или Дт 1030 поступления, KZT | 0 | `doc_id` и строки Кт 6010, либо `doc_id` и строка Дт 1030 |
| `vat_on_top` (из практики) | `invoice_id` | Σ(`total_minor` − `quantity` × `unit_price_minor`) по строкам, валюта счёта | 0 | `doc_id` счёта и его строки Кт 3130 (можно добавить `doc_id` оплаты) |
| `uncollected_service` (из практики) | `invoice_id` просроченного счёта | его `total_minor`, валюта счёта | 0 | `doc_id` просроченного счёта, `doc_id` продления (тот же `service_code`, период начинается на следующий день после конца неоплаченного, выписан после `due_at`) и строки Дт 1210 просроченного счёта |

Типы из практики по умолчанию выключены (`config.errors`). Если в эпизоде их нет, вывод такого типа — обычное ложное срабатывание.

Процитированные ID должны быть показаны агенту в этом эпизоде (`list_records`, `get_record`, `get_document`) и относиться к ошибке: документы затронутых счетов и платежей, их строки книги, курсы этой валюты рядом с нужными датами.

## Награда

```
P = TP/(TP+FP),  R = TP/(TP+FN),  F1 = 2TP/(2TP+FP+FN)
нулевой знаменатель: P или R = 0; эталон и выводы пусты: F1 = 1; эталон пуст, выводы есть: F1 = 0
награда = clip(2·F1 − 1 − 0.002·inspection_steps, −1, 1)
```

`inspection_steps` — число действий до `submit`. Сопоставление ищет максимальное взаимно однозначное паросочетание (`scoring.py`, augmenting paths). Код нормализации, допусков и выбора открыт. Отдельно для диагностики доступна экспериментальная risk-aware награда `materiality_reward` (`python -m audit_env diagnostics`), не заменяющая общую формулу.

## Внешний агент

`runner.py` общается с агентом по JSONL через stdin/stdout. Каждая строка от среды — `{"observation", "reward", "terminated", "truncated", "info"}`, каждая строка от агента — действие.

- Строгий JSON: без дублирующихся ключей и без NaN/∞, кадр не больше 256 КиБ.
- Дедлайн общий на эпизод.
- Процесс агента не наследует переменные `AUDIT_ENV_SECRET` и `AUDIT_ENV_KEY_FILE`: с секретным ключом и открытым кодом генератора эталон закрытого эпизода можно пересчитать. Файл ключа в домашней папке от процесса того же пользователя это не закрывает — границей изоляции служит контейнер агента (`--agent-image`).
- Работает в Windows и Linux: используется поток-читатель вместо `select`.
- `python -m audit_env.agents <policy>` — готовые агенты: `expert`, `inspector`, `reconcile`, `random`, `flag-all`, `micro`.

## Траектории

Каждая строка `trajectories.jsonl` содержит `episode_id, step, action, observation, reward, terminated, truncated`. Шаг 0 — это `{"type": "reset"}` с первым наблюдением. Закрытого эталона в наблюдениях нет.
