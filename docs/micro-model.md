# Микромодель: обучение на среде

```bash
python -m audit_env train          # ~16 с на CPU; пишет models/model.json и models/report.json
python -m audit_env demo --policy micro
python -m audit_env audit <папка> --model models/model.json
```

## Как устроено

1. **Наблюдение.** Агент читает таблицы через публичные действия `list_records`. Это около 16 шагов из 100.
2. **Кандидаты.** `micro.candidates` широко предлагает возможные ошибки всех шести типов:
   - пары счетов одного клиента с одной суммой — на `duplicate_invoice`;
   - каждый признанный счёт и каждое проведённое поступление — на `period_cutoff`;
   - каждый валютный счёт и каждое валютное поступление — на `fx_rate`;
   - каждое поступление со ссылкой и авансом — на `payment_allocation`;
   - каждый счёт с НДС — на `vat_on_top`;
   - каждый счёт без единой оплаты — на `uncollected_service`.

   Сумма и доказательства берутся из тех же публичных записей.
3. **Признаки** считаются только по публичным данным и опубликованным правилам. Например:
   - логарифм расхождения с курсом правильной даты и с курсом «наивной» даты, а также превышает ли расхождение допуск;
   - лежит ли окончание услуги, дата выписки, момент операции или «дата на стене» внутри периода;
   - доля аванса в поступлении и признан ли счёт к моменту оплаты;
   - совпадение строк и периода у пары счетов;
   - доля начисленного сверху НДС и какую часть цены без НДС оплатил покупатель;
   - просрочен ли счёт, продлена ли та же услуга встык после срока, сколько месяцев просрочки.

   ID, порядок записей и seed в признаки не входят.
4. **Модель** — логистическая регрессия для каждого типа: чистый Python, веса сбалансированы по классам, обучение детерминированное. Половина из 120 обучающих эпизодов содержит ошибки из практики.
5. **Обучение по награде среды.** После обучения весов порог отправки выбирается по средней терминальной награде всей политики на train-эпизодах в открытом режиме. Это и есть RL-сигнал среды.
6. **Сравнение на отложенных данных:** dev-сплит и оба закрытых шаблона со свежими seed и секретным ключом, против `reconcile`, `expert` и `oracle`. Dev и закрытые шаблоны при обучении не используются.

## Результат (models/report.json)

Средняя награда:

| Сплит | Политика | Чистые | Одна ошибка | Смесь | Взаимодействия | Ошибки из практики |
|---|---|---|---|---|---|---|
| dev | micro | +0.977 | +0.974 | +0.966 | +0.973 | — |
| dev | reconcile | −1.000 | −0.567 | −0.686 | −0.764 | — |
| holdout | micro | +0.974 | +0.971 | +0.968 | +0.969 | — |
| holdout | reconcile | −1.000 | −0.501 | −0.416 | −0.610 | — |
| extended | micro | +0.969 | — | +0.964 | — | +0.973 |
| extended | reconcile | −1.000 | — | −0.596 | — | −1.000 |

На всех отложенных наборах F1 модели = 1.0. На 200 эпизодах разбора сбоев (`python -m audit_env failures`, `--extended`) модель нашла все 720 ошибок без ложных срабатываний.

Улучшение относительно простой сверки измерено только на отложенных данных; на реальные бухгалтерии этот результат не переносится без отдельной проверки.

## Как подключить своё обучение

Траектории в открытом режиме (`data/trajectories.jsonl`, `data/trajectories/*.jsonl`) и контракт `reset`/`step` подходят для любого RL-алгоритма. Модель, обученная вне репозитория, подключается как агент через `runner.run_subprocess` (JSONL по stdin/stdout) или в отдельном контейнере (`demo --agent-image`). В закрытом режиме обратной связи о правильности нет.

Обвязка для LLM (`llm*.py`, `hf_*.py`, `rag_env.py`, `docs/llm-training.md`) написана под первую предметную модель прототипа и в проверку не входит.
