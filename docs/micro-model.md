# Микромодель: обучение на среде

```bash
python -m audit_env train          # ~12 с на CPU; пишет models/model.json и models/report.json
python -m audit_env demo --policy expert
python -m audit_env audit <папка> --model models/model.json
```

## Как устроено

1. **Наблюдение.** Агент читает таблицы через публичные действия `list_records`. Это около 14 шагов из 100.
2. **Кандидаты.** `micro.candidates` широко предлагает возможные ошибки всех четырёх типов:
   - пары счетов одного клиента с одной суммой;
   - каждый признанный счёт и каждое проведённое поступление как кандидаты на `period_cutoff`;
   - каждый валютный счёт и каждое валютное поступление как кандидаты на `fx_rate`;
   - каждое поступление со ссылкой и авансом как кандидат на `payment_allocation`.

   Сумма и доказательства берутся из тех же публичных записей.
3. **Признаки** считаются только по публичным данным. Например:
   - логарифм расхождения с курсом правильной даты и с курсом «наивной» даты;
   - лежит ли окончание услуги, дата выписки, момент операции или «дата на стене» внутри периода;
   - доля аванса в поступлении;
   - признан ли счёт к моменту оплаты;
   - совпадение строк и периода у пары счетов.

   ID, порядок записей и seed в признаки не входят.
4. **Модель** — логистическая регрессия для каждого типа: чистый Python, веса сбалансированы по классам, обучение детерминированное.
5. **Обучение по награде среды.** После обучения весов порог отправки выбирается по средней терминальной награде всей политики на train-эпизодах в открытом режиме. Это и есть RL-сигнал среды.
6. **Сравнение на отложенных данных:** dev-сплит и шаблон закрытой проверки со свежими seed и секретным ключом, против `reconcile`, `expert` и `oracle`. Dev и закрытый шаблон при обучении не используются.

На закрытом шаблоне модель пропускает 1 из 30 ошибок во взаимодействиях. Эксперт по правилам находит всё. Улучшение относительно простой сверки измерено только на отложенных данных; на реальные бухгалтерии этот результат не переносится без отдельной проверки.

## Как подключить своё обучение

Траектории в открытом режиме (`data/trajectories.jsonl`, `data/trajectories/*.jsonl`) и контракт `reset`/`step` подходят для любого RL-алгоритма. Модель, обученная вне репозитория, подключается как агент через `runner.run_subprocess` (JSONL по stdin/stdout). В закрытом режиме обратной связи о правильности нет.

Обвязка для LLM (`llm*.py`, `hf_*.py`, `rag_env.py`, `docs/llm-training.md`) написана под первую предметную модель прототипа и в проверку не входит.
