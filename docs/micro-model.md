# Обучение, RAG и мониторинг

Запустите `make micro-demo`. Python 3.11+ на CPU обучит модель, сравнит её с нулевыми весами и сверкой по правилам на dev, после чего запустит отдельный эпизод в закрытом режиме. Третьи библиотеки, сеть и API не нужны. Команда `make docker-micro` загружает те же параметры в образ агента и повторяет прогон в отдельном контейнере без сети.

## Как проходит сигнал

1. Агент читает страницы счетов, платежей и проводок через публичные действия среды. Область поиска ограничена одним эпизодом.
2. `rag.py` индексирует выданные записи по ссылкам на счёт и платёж и поддерживает поиск по словам. При расчёте признаков модель использует связи с первичными документами. Для ручной проверки доступна команда `python3 -m audit_env retrieve payment_suspense --table ledger`.
3. `micro.py` оценивает кандидат в ошибку логистической моделью из восьми весов и смещения. Суммы из документов, количества проводок, доли денежных расхождений и прочие признаки вычисляются по публичным записям. ID, порядок документов и seed не входят в вектор.
4. При превышении порога структурированный генератор собирает вывод из записей. Он вычисляет сумму, проверяет валюту, подставляет ссылки и формирует краткое объяснение по шаблону. Если из наблюдений нельзя обосновать сумму и набор доказательств, кандидат не попадает в ответ. Оценщик отдельно сверяет вывод с закрытым эталоном.
5. Монитор на стороне проверяющего получает действие и ответ на каждом шаге. В конце он сохраняет счётчики действий и запросов, ошибки, лимит шагов, время, количество просмотренных доказательств, количество выводов и флаги по ссылкам на непрочитанные записи и повторным выводам.

Формирование ответа выполняется шаблонами. Микромодель обучена выбирать кандидатов, а маршрут обхода таблиц фиксирован и подходит для текущих размеров эпизода.

## Артефакты

| Файл в `build/micro/` | Что в нём |
| --- | --- |
| `model.json` | Версия формата, имена признаков, веса, смещение и порог |
| `train_examples.jsonl` | Векторы признаков и метки из train |
| `report.json` | Метрики на dev для нулевых весов, обученной модели и сверки по правилам |
| `trajectory.jsonl` | Закрытая траектория демо, терминальная награда скрыта |
| `monitor.json` | Агрегированный отчёт монитора |
| `docker-trajectory.jsonl`, `docker-monitor.json` | Те же журналы отдельного контейнера агента |

Метки присоединяются после сбора публичных наблюдений. Оптимизатор использует только train. Из-за редкости ошибок градиент взвешивается по классу. Dev используется для расчёта метрик после фиксации весов и порога. В образ агента копируется только модель и код вывода. Таблицы разметки и отчёты остаются у проверяющего.

## Куда подключать своё обучение

Для дополнительных конфигураций передайте `python3 -m audit_env train --suite configs/my-suite.json --output build/my-model`. При смене признаков обновите `FEATURES` и `MODEL_VERSION`, обучите модель заново и прогоните новую dev-выборку с чистыми случаями и взаимодействующими ошибками.

Текущий алгоритм обучается с учителем. Для будущего RL используйте прежний `reset/step` и терминальную награду открытого режима. `make dataset` экспортирует записи и JSONL-траектории с действиями, наблюдениями и наградами. Следующий агент может заменить фиксированный маршрут на обучаемую политику, сохранив тот же протокол, RAG, монитор и оценщик. Закрытая оценка должна оставаться без обратной связи о правильности.
