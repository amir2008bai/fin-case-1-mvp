# Чек-лист агентного бенчмарка (ABC — Agentic Benchmark Checklist)

Оценка среды `audit_env` (`v2.1.0`, архив `fin-case-1-mvp-v2.1.4.zip`) по чек-листу **Agentic Benchmark Checklist (ABC)** из статьи Zhu et al., *"Establishing Best Practices for Building Rigorous Agentic Benchmarks"* ([arXiv:2507.02825v4](https://arxiv.org/html/2507.02825v4), открыта и сверена полностью).

Статусы: **выполнено**, **частично**, **нет** (включая честную пометку неприменимых категорий из статьи).

---

## Ключевые опоры валидации (сводка для жюри)

| Опора | Как реализовано в `audit_env` | Подтверждение (тест / команда) |
|---|---|---|
| **Do-nothing agent** («пол молчания») | В `python -m audit_env jury` вычисляется `silence_floor`: пустой ответ без шагов даёт `+1.0` на чистом эпизоде и `-1.0` на эпизоде с ошибками; на протоколе из 20 закрытых эпизодов (5 чистых, 15 с ошибками, seed 7) пол молчания равен **`-0.500`**, а нормализованная метрика равна `(return - floor) / (oracle - floor)`. | `python -m audit_env jury`, `audit_env/jury.py`, `tests/test_jury.py::test_jury_protocol_20_closed_episodes_and_20_paired_checks` |
| **Oracle solvability** | Автоматический оракул решает 20/20 закрытых эпизодов жюри с `F1 = 1.000`, `clean FP = 0.0`, `return = +0.980` (`95% CI [+0.970, +0.987]`) и проходит 20/20 парных преобразований. Независимая проверка правды (`checks.py`) сверяет сгенерированные ошибки без доступа к секрету генератора. | `python -m audit_env jury`, `tests/test_world.py::test_random_configs_prove_truth_independently`, `tests/test_jury.py::test_paired_check_also_compares_the_independent_auditor` |
| **Shortcut / leakage** | Раздел 10 `verify` проверяет AUROC по 8 признакам представления (порог `|AUROC - 0.5| <= 0.06`) и 7 структурным признакам (порог `<= 0.08`, включая `revenue_posting_time`, `goods_waybill`, `cited_by_receipt`, `receipt_lag_days`, `customer_invoices`, `invoice_amount_digit`, `payment_amount_digit`) на 360 закрытых эпизодах. | `python -m audit_env verify` (раздел 10), `audit_env/leakage.py`, `tests/test_structural_tells.py::test_structural_features_stay_near_chance` |
| **Grader robustness** | 12 red-team атак в разделе 8 `verify` (ни одна не нарушает инварианты), модульные мутационные проверки в `tests/test_gaps.py`, фаззинг в `tests/test_fuzz.py`, а также независимый мутационный прогон `tools/grader_mutation.py` (`60/60 = 100%` убитых мутантов: 10 граничных мутантов, выживших в первом прогоне, убиты тестом `tests/test_scoring_boundaries.py`). | `python -m audit_env verify` (раздел 8), `tests/test_gaps.py`, `tests/test_attacks.py`, `python tools/grader_mutation.py` |
| **Reproducibility** | Раздел 4 `verify` проверяет побайтовую идентичность закоммиченных открытых эпизодов свежему экспорту; кросс-процессный тест с разными `PYTHONHASHSEED` и закрытым/read-only `HOME` проверяет детерминизм `reset`/`step`. | `python -m audit_env verify` (раздел 4), `tests/test_gaps.py::test_cross_process_reset_step_reproducibility_subprocess`, `tests/test_repro.py::test_files_are_byte_identical_across_hash_seeds` |
| **Reporting with uncertainty** | `audit_env/jury.py` считает 95%-ный перцентильный бутстреп-интервал (`BOOTSTRAP_SAMPLES = 2000`) для средней награды каждой политики и печатает его в таблице. | `python -m audit_env jury`, `audit_env/jury.py` (`bootstrap_ci`), `tests/test_jury.py::test_jury_cli_and_reproducible_report` |

## Часть 2. Outcome Validity (`O.a–O.i`)

В ABC критерии `O.a–O.i` разделены по типу оценки задачи: *Information acquisition* (`O.a–O.c`), *Code testing* (`O.d–O.f`), *State matching* (`O.g`), *Multistep reasoning* (`O.h–O.i`). В `audit_env` оценка — детерминированное сопоставление структурированного списка находок (`submit`) с `truth` (1-to-1 matching по типу, `affected_ids`, валюте, сумме с допуском и просмотренным достаточным доказательствам).

| Пункт ABC | Требование (Zhu et al., arXiv:2507.02825v4) | Статус | Подтверждение (тест / файл / команда) | Честная оговорка |
|---|---|---|---|---|
| **O.a.1–O.a.2** | Извлечение информации: точное совпадение строк/сущностей без ложных отказов на эквивалентных ответах. | **выполнено** | `tests/test_scoring.py::test_matching_is_one_to_one_and_order_free`, `test_guessed_ids_type_currency_and_tolerance`, `tests/test_security_and_invariants.py::test_honest_fx_citation_accepted_on_interacting_errors`. | Текст `explanation` намеренно не оценивается, чтобы исключить persuasion-атаки. |
| **O.b.1–O.b.3** | Извлечение информации: защита от перебора подстрок/списков и угадывания. | **выполнено** | `tests/test_scoring.py::test_flag_everything_scores_badly`, `test_repeats_give_no_gain`, `test_evidence_must_be_seen_relevant_and_complete`, `tests/test_attacks.py::test_hedging_and_repeats_lose_reward`. | — |
| **O.c.1** | Оценка через LLM-судью (валидация согласия с людьми). | **нет (не используется)** | Оценщик полностью детерминированный (`audit_env/scoring.py`), LLM-судья намеренно не применяется. | Это осознанный выбор в пользу нулевой дисперсии и устойчивости к persuasion-атакам. |
| **O.d.1–O.f.2** | Тестирование кода (unit-тесты сгенерированного кода, фаззинг, E2E). | **нет (не применимо к выходу агента)** | Агент сдаёт JSON-находки, а не программный код. Для **самого оценщика** реализованы фаззинг (`tests/test_fuzz.py`) и мутационное тестирование (`tools/grader_mutation.py`: `60/60 = 100%`). | Граничные мутанты (длины, валюта, `MAX_AMOUNT_MINOR`, нестрогое `<=` для доказательств) покрыты `tests/test_scoring_boundaries.py`; мутации вне `scoring.py` не проверялись. |
| **O.g.1–O.g.3** | Сопоставление состояний: учёт всех допустимых эквивалентных решений, релевантных и нерелевантных данных, нетривиальная сложность. | **выполнено** | `tests/test_world.py::test_each_evidence_set_is_independently_sufficient`, `test_interactions_put_two_issues_on_one_receipt`, `test_distractors_are_present`, `tests/test_security_and_invariants.py::test_empty_relevant_ids_does_not_allow_evidence_padding`. | — |
| **O.h.1** | Многошаговое рассуждение: явный формат финального ответа. | **выполнено** | `schemas/`, `tests/test_schema_validation.py`, `tests/test_brief_criteria.py::test_brief_05_submission_limits_and_malformed_gives_minus_one`, `tests/test_llm_agent_compat.py::test_gemini_and_openai_strict_schema_compliance`. | — |
| **O.h.2** | Многошаговое рассуждение: защита от угадывания ответа без рассуждения/просмотра данных. | **выполнено** | `audit_env/scoring.py` (`evidence <= seen`), `tests/test_gaps.py::test_mutation_scoring_seen_evidence_check_is_enforced`, `tests/test_economy.py::test_reading_half_or_none_of_the_ledger_loses_reward`. | — |
| **O.i.1** | Метрика качества коррелирует с реальным аудитом, а не со взломом метрики. | **выполнено** | `tests/test_attacks.py::test_honest_work_is_the_best_strategy_on_erroneous_books`, `test_accusations_on_clean_books_lose_to_silence`, `tests/test_security_and_invariants.py::test_materiality_reward_blocks_zero_amount_fp_flooding`, `tests/test_diagnostics.py::test_diagnostics_reports_official_and_experimental_separately`. | Официальная награда (`2*F1 - 1 - 0.002*steps`) не взвешивает ошибки по сумме; взвешенная по существенности метрика (`MaterialityScore`) выделена отдельно как экспериментальная. |
