# Финансовый кейс 1

Командный репозиторий для MVP хакатона.

- [Текущая стадия и история изменений](PROJECT_STATUS.md)
- [Правила ведения журнала для агентов](AGENTS.md)

Воспроизводимая среда аудита синтетических компаний. Первый релиз покрывает два вертикальных сценария: дубли счёта и полное или частичное нераспределение платежа. В обоих случаях скриптовый агент может найти расхождение по открытым записям и получить оценку от отдельного проверяющего.

## Быстрый старт

Нужен Python 3.11+ на macOS или Linux. Python-пакеты устанавливать не требуется. В Docker зафиксирован Python 3.11.14; для настройки сети и файловой изоляции используйте Docker Engine.

```bash
make verify       # тесты, четыре политики, 20 открытых эпизодов и 20 пар с новыми ID
make demo         # скриптовая сверка и один JSON с метриками
make dataset      # 10 train + 10 dev, эталон и trajectories.jsonl в build/open-dataset
make docker-verify
make docker-agent # отдельный контейнер агента для одного закрытого демо
```

Без Make запустите из корня `python3 -m unittest discover -s tests -v` и `python3 -m audit_env benchmark`. Экспорт требует нового каталога, можно передать `make dataset DATASET=build/run-02`. Первый Docker build может скачать базовый образ. После загрузки образов тестовый и закрытый прогоны работают с отключённой сетью.

```bash
mkdir -p build
python3 -m audit_env demo --closed --policy reconcile --trajectory build/closed.jsonl
```

CLI печатает метрики на стороне проверяющего после окончания эпизода. Ключ `--closed` скрывает терминальную награду из контракта и траектории. Для изоляции произвольного кода агента добавьте `--agent-image fintech-audit:agent` после сборки образа. Без `--agent-image` запускаются доверенные встроенные политики. Подробности в [протоколе](docs/protocol.md).

## Статус покрытия

- Готовы два типа ошибок, чистые эпизоды, законные частичные оплаты и разные счета с одинаковой суммой. Текущие операции идут в KZT, `fx.csv` содержит заголовок.
- Два типа могут присутствовать в одном эпизоде на разных операциях. Взаимодействие ошибок на одной операции, валютные сценарии, отсечение периода и возвраты входят в продолжение проекта.
- Двадцать конфигураций и seed в репозитории открытые. Для закрытой проверки проверяющий подставляет свой seed и конфигурацию. Сопоставимость проверяется на локальном наборе и преобразованных парах.
- Скриптовая сверка покрывает базовые шаблоны. Её показатели на этих данных проверяют работоспособность среды.

## Обучение микромодели и RAG

```bash
make train
make micro-demo
make docker-micro
python3 -m audit_env retrieve payment_suspense --table ledger --limit 3
```

Микромодель учится определять, какие счета и платежи стоит отметить. Она получает числовые признаки из найденных документов и проводок. Генератор ответа собирает сумму и ссылки на доказательства из тех же записей. В `build/micro/` сохраняются обучающие примеры, параметры модели, метрики на отдельном dev-наборе, траектория и отчёт монитора.

[Устройство обучения, retrieval и мониторинг](docs/micro-model.md)

## Дообучение большой модели

`make llm-data` создаёт диалоги аудита для SFT, пары предпочтений и траектории с наградами. Модель может вызывать RAG через `search_records` и находить кандидатов через `group_ledger`. Для локальной модели добавлены команды LoRA SFT, RL по терминальной награде среды и оценка на dev. Для этих команд нужны опциональные зависимости из `requirements-llm.txt`.

[Рецепт обучения, форматы и ограничения](docs/llm-training.md)
